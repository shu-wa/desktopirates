# 数千時間遊べる航海ゲームへのロードマップ

## 設計原則

数千時間を「必要経験値を増やす」だけで作らない。長期プレイを支える中心は、次の三つとする。

1. 同じ装備でも組み合わせと状況で答えが変わるビルド構築
2. 定期的に新しい目標とルールが生まれる再航海
3. 集めた船、知識、記録が恒久的に蓄積する船長生活

Path of Exile の Challenge League は、本編の所有物を残しながら新経済で再出発する構造を採用している。No Man's Sky の Expedition は、共通の出発点、順不同のマイルストーン、段階報酬を一つの期間航海へまとめている。本作ではこの考え方を、放置型デスクトップゲームを邪魔しない短い「遠征航路」へ変換する。

## 優先度 A: 基盤とリプレイ性

### 海域深度と変異海域

- 港を出るたびに海流、天候、敵勢力、資源、状態異常耐性の組み合わせが変わる。
- 深度を上げると複数の危険修飾子が付き、報酬テーブルも上がる。
- 深度は無限に数値化せず、一定段階ごとに新しい判断を要求する敵 AI や海域ルールを解放する。

### 契約生成

- 護衛、救助、海図測量、密輸、賞金首、残骸連鎖、港防衛を基本型にする。
- 目的、航路、妨害、選択肢、報酬を別データにし、組み合わせで航海物語を作る。
- 契約途中の判断で派閥、港の価格、次の敵、結末を変える。

### ビルドの横方向拡張

- 大砲、船員、パーク、船体区画、弾薬、船長方針をロードアウトとして保存する。
- 炎上特化、状態異常治療、側面一斉射、逃走交易など、異なる勝ち筋を成立させる。
- 重複パークには逓減、相互作用、条件発動を用意し、単一の最適解を避ける。
- ドロップには天井となる救済値、不要品の分解、狙った系統へ寄せる加工を設ける。

## 優先度 B: 生きた世界

### 派閥と港湾経済

- 港ごとに食料、水、弾薬、部品の生産と需要を持たせる。
- 海賊襲撃、護送成功、ボス撃破で安全度、価格、品揃え、造船設備が変化する。
- 修理費、船員給料、船体保険、加工、再抽選を資金の恒久的な使い道にする。

### ボス変異と艦隊戦

- 同じボスでも部位、随伴艦、攻撃順、状態異常、海域ギミックを変える。
- 討伐周回にはランク別パークだけでなく、見た目、航跡、帆、船首像、称号を混ぜる。
- 失敗しても研究値や観測記録が残り、次回の対策が進む。

### 船長の記録

- 海図アトラス、敵図鑑、残骸コレクション、港史、ボス航海記録を恒久進行にする。
- 発見率だけでなく「どの構成で、どの深度を、何分で越えたか」を残す。
- レア船体は性能差だけでなく、輪郭、甲板配置、砲門配置による遊びの差を持たせる。

## 優先度 C: 継続運営とコミュニティ

### 遠征航路

- 6〜10 週間ごとに専用シード、専用ルール、段階目標を配信する。
- 本編を捨てさせず、遠征で得た外観と称号を通常セーブへ持ち帰れるようにする。
- 期間終了後は復刻または常設化し、取り逃しによる圧迫感を抑える。

### 非同期のつながり

- 他の船長の航跡ゴースト、週間航路タイム、共有された海図断片を表示する。
- 常時オンラインの協力プレイを必須にせず、デスクトップ放置の軽さを守る。
- オフライン航海は安全で控えめな収益、能動操作は危険だが高い選択報酬にする。

### MOD と Steam Workshop

- 契約、敵、戦利品、船体外観をデータ駆動にし、検証可能な MOD 形式を先に定義する。
- 最初は公式テンプレートとローカル MOD 読み込み、その後 Steam Workshop に接続する。
- Steamworks は Workshop を、ユーザーが制作物を保存、整理、評価、購読できる仕組みとして提供しているため、公式コンテンツだけでは到達できない長期的な海域拡張に向く。

## 放置ゲームとして守る UX

- バックグラウンド時の CPU/GPU 上限とフレームレートを明示設定する。
- 戦闘、港到着、食料不足など、通知する事件をプレイヤーが選べるようにする。
- 終了時に航海の短い日誌を出し、放置中に何が起きたかを一画面で理解できるようにする。
- 重要な失敗は入力不能中に確定させず、救援待ちや退避猶予へ変換する。
- 長時間プレイの報酬を連続起動時間ではなく、判断、収集、構成発見へ置く。

## 実装順

1. セーブ移行、ドロップ検証、バランス計測、ロードアウト保存
2. 契約生成、装備接辞、アトラス、不要品分解、経済の消費先
3. 変異海域、ボス変異、派閥港湾経済、難度階層
4. 遠征航路、週間シード、非同期ゴースト
5. MOD スキーマ、検証ツール、Steam Workshop

この順番なら、先に一人用ゲームとして遊びの組み合わせを成立させ、その後に運営要素とコミュニティ要素を安全に載せられる。
